## Principle

The work remains the primary surface. Videogo explains what it has observed, what that supports and what useful action follows, without making the owner manage experiments or an ontology. Learning may improve or confirm a decision; it need not generate an alert, a new task or a new policy on every update.

Mission direction: discover which messages drive business outcomes and put them to work. The UI must not present the mission as already proven customer lift. The organic-video MLP and existing actual permissions remain; paid and wider GTM execution do not appear merely because the system can describe a future validation plan.

## Explicit behavioral conflict and proposed resolution

The frozen design principles say a claim only ever moves up. That cannot describe **current advice** after contradictory evidence, metric correction, offer change, lost permission or expired applicability.

Proposed amendment: preserve historical versions and their original evidence status, but allow the current recommendation to be narrowed, suspended, superseded or withdrawn. Existing collecting/early/learned visual vocabulary can remain; do not create a new color system or compulsory status dashboard. A concise 'Updated' explanation inside the existing relevant work object can identify what changed and the next permitted action. Formal EXPERIENCE acceptance remains required; this document does not silently alter the freeze.

## End-to-end review cases

| Moment | Minimal interaction / truthful surface | What must happen underneath |
|---|---|---|
| First video, no history | Actual useful video and compact proposed next plan; no 'we learned what converts' | Business context/operator priors are not account market evidence |
| Optional initial media | Add media, honest intake, no compulsory asset setup | Rights/quality relevance, not automatic proof or use of every upload |
| Owner corrects a fact | Acknowledge appropriate correction and effect on work | Confirm protected identity where required; invalidate affected future use; no wait for audience window |
| Owner changes taste | Apply the scoped edit and show the relevant difference; durable scope only when justified/authorized | Exact referent/version and source; no global taste inferred from silence or one local request |
| Owner brings an idea | Connect the underlying intention to relevant work; offer one useful evidence-backed refinement | Preserve authorship and novelty; lack of prior performance is not falsehood |
| Early audience clue | 'This is worth testing further' plus the next meaningful step only when worth surfacing | No causal or profitability claim from engagement; preserve uncertainty and counterevidence |
| Supported contextual finding | Explain the specific result and what it changes—or why continuing makes sense | Current evidence, scope, policy stage and permissions; no universal winner language |
| Contradictory/corrected evidence | 'I am narrowing the earlier recommendation because…' within the existing object | New version/reassessment; old rationale remains historical, not a live default |
| Measurement unavailable | Unknown/coverage explanation, not zero and not invented failure | Metric-specific source coverage and observation window |
| Production/publication fails | Report the actual blocked/partial/unknown work state | No negative market inference; existing recovery/authorization |
| Useful service continues while results mature | No new owner chore; show work moving when relevant | Separate due work from deeper inference; no research-driven service starvation |
| Evidence suggests a non-video bottleneck | Concise diagnosis or appropriate next question | Do not activate an unpurchased channel, spend or new tool automatically |
| Stronger validation requires new access | Ask only for the justified source/action when actually supported; allow decline | Source, analysis, execution and public permissions stay distinct |
| An external agent reads knowledge | Bounded contextual answer with limitations and version | No implicit write/publish/identity/spend grant; current validity checked |
| An obsolete instruction is corrected | Show the new scope and relevant future impact | Repair durable memory and dependent work, not just the visible artifact |
| No worthwhile change | 'Nothing needed from you' where appropriate | Maintaining a good decision is a valid result, not a failure to learn |

Example copy is illustrative, not a set of measured findings. Numerical effect statements appear only when the actual method/evidence supports them, with accessible scope and uncertainty. Do not expose a model's self-confidence as a causal confidence badge. A public statement that a message 'works' must resolve what outcome, audience, comparison and conditions that means.

## Continuity and proactivity

Today surfaces genuine needs, ready actions, worthwhile next work and qualified learned implications; Studio retains all actual content; Knowledge exposes understandable facts and scoped direction; Connections handles actually supported routes. General/contextual composer remains secondary and clearable. No fifth Learning destination or mandatory experiment setup.

Proactive contact is meaningful and deduplicated through an actual supported chosen route. A retrieved claim or an external-model connection does not prove unsolicited push capability. Deep links preserve work/version context, and stale edits do not silently target the newest artifact.

'Change this', 'remember this' and 'publish this version' remain separate intentions. Existing Publish/Schedule/Change/Reject action semantics and exact final authorization remain. A background inference may recommend, not grant itself permission. An obvious explicit local edit should not incur redundant consent ceremony; a material identity/claim/cost/public consequence must remain visible.

## T1/T2 and launch focus

Advanced implicit taste/tone/copy adaptation remains reserved; explicit scope and correction provenance are defined now. Detailed camera-aware capture app remains reserved; current owner-only optional capture/consent/decline baseline stays and first value requires no new recording. Neither is silently removed from its actual contractual scope or implemented by this design note.

## Acceptance before adoption

Check first-value comprehension, ability to identify the next plan, correct target/scope, meaningful memory reuse, changed advice comprehension, honest unknowns, hands-off use, few unnecessary interruptions, accessibility and recovery/revoke. Verify all changes against actual product EXPERIENCE/rights and the pinned/approved design sources.

These are review scenarios, not executed interface tests. The prior A3 browser checks do not validate this new behavioral amendment. Independent product/design review and applicable EXPERIENCE reconciliation are required. Do not modify the existing checkpoint or PR3 writer branch to imply acceptance.
